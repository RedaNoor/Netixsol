<h1 align="center">SQL Aggregation, Subqueries and CTEs</h1>

## Overview

This task builds on SQL JOINs by introducing aggregation, subqueries, Common Table Expressions (CTEs), and window functions. The goal is to answer more complex business questions by summarizing data, breaking queries into smaller steps, and ranking results.

## When to Use Each SQL Feature

### Subquery

Use a subquery when another query depends on the result of a smaller query.

Example: Customers spending above the average customer.

### CTE

Use a CTE when a query has multiple logical steps and readability is important.

Example: Ranking customers after calculating their total spending.

### Window Function

Use window functions when calculations should keep every row instead of grouping everything into one row.

Example:
1. Ranking customers within each city.
2. Finding the latest rental for every customer.

**Note**: use a subquery for a one-off value, a CTE to organize a multi-step query, and a window function whenever the output needs to stay row-level while still comparing against a group.

## Business Questions

### Part 1: Aggregation Basics

#### 1. Calculate total revenue generated by each store.

**Explanation:** payment -> staff -> store. Grouped payment by store (via staff) and summed the amount using SUM().

#### 2. Find the average rental duration for each film category.

**Explanation:** This query joins the film, film_category, and category tables. It groups films by category and uses AVG() to calculate the average rental duration for each category.

#### 3. Count rentals made each month.

**Explanation:** This query truncates the rental date down to the month, groups rentals by that month, and counts the total number of rentals in each one using COUNT().

#### 4. Find categories containing more than 50 films.

**Explanation:** This query groups films by category and counts how many films belong to each one. The HAVING clause filters the grouped result to show only categories that contain more than 50 films, since WHERE can't filter on a count that doesn't exist until after grouping.

### Part 2: Subqueries

#### 5. Find customers who spent more than the average customer.

**Explanation:** A subquery in FROM computes total spend per customer; a second subquery averages those totals; the outer query's HAVING clause keeps only customers above that average.

#### 6. Find the highest rental-rate film in each category.

**Explanation:** A correlated subquery checks, for each film, whether its rental_rate equals the max rate within its own category. The inner query re-runs per outer row since it references fc.category_id from the outer query.

#### 7. Find customers who never rented a film.

**Explanation:** Used NOT EXISTS (safer than NOT IN when NULLs are possible) to find customers with no matching row in rental.

#### 8. Find the store with the highest revenue.

**Explanation:** Computed revenue per store in a subquery, then filtered WHERE total_revenue = (subquery for MAX) to isolate the top store.

### Part 3: CTEs & Window Functions

#### 9. Rank customers by total spending within each city.

**Explanation:** A CTE (customer_spend) computes total spend per customer per city; RANK() OVER (PARTITION BY city ORDER BY total_spent DESC) ranks them within each city without losing individual rows.

#### 10. Find each customer's most recently rented film.

**Explanation:** A CTE assigns ROW_NUMBER() per customer ordered by rental_date DESC; filtering WHERE rn = 1 returns just the latest rental per customer.

#### 11. Calculate month-over-month rental revenue growth.

**Explanation:** A CTE calculates total revenue earned each month. The LAG() window function compares each month's revenue with the previous month, letting the growth percentage be calculated in the same query.

#### 12. Find the top three highest-grossing films in each category.

**Explanation:** A CTE calculates the total revenue earned by each film. RANK() is then used to rank films within each category, and only the top three films from every category are returned.

#### Bonus Question: Which staff member processed the highest revenue in each store, and what percentage of that store's total revenue did they contribute?

**Explanation:** The first CTE calculates revenue generated by each staff member. The second CTE sums that up into each store's total revenue. RANK() then identifies the highest-earning staff member per store, and their contribution percentage is calculated by dividing their own revenue by their store's total.

## Business Insights

### Insight 1: Store Performance

Store 2 generated slightly more revenue than Store 1, earning `$31,059.92` compared to `$30,252.12`. The gap is small, so both stores are performing at a similar level overall.

### Insight 2: Staff Revenue ConcentratioN

The bonus query shows something the store-level totals hide: each store has exactly one staff member processing its payments, so that single employee accounts for 100% of their store's revenue (Mike Hillyer at Store 1, Jon Stephens at Store 2). There's no backup staff member sharing the load at either location, which is a real dependency risk worth knowing about, not just an interesting number.

### Insight 3: Film Performance

Revenue doesn't track catalog size. Categories with over 50 films each (Sports, Foreign, Family, Documentary, Animation, Action) aren't necessarily the top earners, since a handful of consistently popular titles can outperform a much bigger catalog. For example, "Fool Mockingbird" led the Action category at `$162.79`, while "Dogma Family" topped Animation at `$168.72`. Promoting proven favorites like these is likely to move the needle more than simply stocking more titles in a category.

**An extra insight:** rental volume and revenue growth don't move together month to month. The number of rentals rises and falls, and the month-over-month growth percentage swings between strongly positive and negative rather than following a steady trend, so revenue can't be predicted from rental counts alone.
